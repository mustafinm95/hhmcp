# hhmcp

`hhmcp` — локальное кроссплатформенное приложение для сбора и ведения личной
библиотеки публичных вакансий hh.ru. Оно использует Playwright и Chromium,
хранит данные в SQLite и предоставляет одинаковые операции через CLI и MCP по
stdio. Авторизация на hh.ru, действия в аккаунте и API hh.ru не используются.

Проект находится на ранней стадии разработки. Формат команд и моделей до версии
1.0 может меняться.

## Требования и установка

- Python 3.12 или новее;
- Windows, macOS или Linux;
- доступ Chromium к публичным страницам hh.ru.

Создайте виртуальное окружение, установите пакет и браузер:

```console
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m playwright install chromium
```

macOS и Linux:

```bash
source .venv/bin/activate
python -m pip install -e .
python -m playwright install chromium
```

На Linux Playwright может запросить системные библиотеки. Если они отсутствуют,
установите их поддерживаемым Playwright способом:

```console
python -m playwright install --with-deps chromium
```

Для разработки установите дополнительный набор зависимостей:

```console
python -m pip install -e ".[dev]"
```

## Быстрый старт CLI

Проверить Python, SQLite, FTS5, каталог данных и Chromium:

```console
hhmcp doctor
```

Создать сохранённый поиск и запустить сбор:

```console
hhmcp saved-search set python-moscow '{"text":"python","area":["1"]}'
hhmcp run python-moscow
```

Можно выполнить разовый поиск по структурированным фильтрам или по HTTPS URL
выдачи hh.ru. Эти два способа нельзя смешивать в одном запросе:

```console
hhmcp search --text python --area 1 --experience between1And3
hhmcp search --url "https://hh.ru/search/vacancy?text=python&area=1"
```

Структурированные фильтры преобразуются в URL выдачи. После перехода hhmcp
проверяет, что hh.ru сохранил запрошенные параметры; управление фильтрами через
нестабильные элементы интерфейса для этого не требуется.

Основные группы команд:

| Команда | Назначение |
| --- | --- |
| `search` | создать и запустить разовый поиск |
| `vacancy` | прочитать подробности вакансии |
| `employer` | прочитать работодателя |
| `saved-search` | управлять сохранёнными поисками |
| `run` | запустить пакет сохранённых поисков |
| `run-status`, `run-resume`, `run-cancel`, `run-results`, `run-compare` | управлять запуском и сравнивать результаты |
| `library` / `library-update` | искать и изменять локальную библиотеку |
| `profile` | управлять профилями кандидата |
| `rank` | оценивать вакансии по выбранному профилю |
| `history` | читать версии вакансии |
| `similar` | найти похожие перепубликации без автоматического объединения |
| `stats` | строить локальную статистику |
| `export` | экспортировать JSON, CSV или Markdown |
| `doctor` | диагностировать установку и окружение |
| `mcp` | запустить MCP-сервер по stdio |

Добавьте `--help` к команде для актуального набора параметров. Команды
`search`, `vacancy`, `employer` и `library` поддерживают `--json`.
Остальные команды чтения сразу возвращают JSON. Ошибки
и диагностика пишутся отдельно от JSON/stdio-протокола.

Локальные статусы (`новое`, `интересно`, `откликнулся`, `интервью`,
`предложение`, `отказ`, `скрыто`), избранное, теги и заметки не отправляются на
hh.ru и сохраняются при обновлении карточки.

## Подключение MCP

MCP-сервер запускается командой:

```console
hhmcp mcp
```

Пример конфигурации MCP-клиента, если пакет установлен в отдельное виртуальное
окружение:

```json
{
  "mcpServers": {
    "hhmcp": {
      "command": "C:/path/to/hhmcp/.venv/Scripts/hhmcp.exe",
      "args": ["mcp"]
    }
  }
}
```

На macOS/Linux укажите путь `.venv/bin/hhmcp`. Сервер использует stdout только
для MCP-протокола; диагностические сообщения направляются в stderr.

Запуск сбора через MCP сразу возвращает `run_id`. Дальнейший статус, краткие
результаты и полные карточки запрашиваются отдельными операциями. Работник живёт
в процессе MCP-сервера: завершение сервера прерывает активный сбор, а отдельный
фоновый демон не создаётся.

## Данные, восстановление и экспорт

Приложение хранит SQLite-базу и межпроцессную блокировку в локальном каталоге
данных. Один каталог допускает только один активный сборщик; другие процессы в
это время могут читать библиотеку. Незавершённый запуск после аварии продолжает
работу через MCP-операцию возобновления. CLI выполняет сбор синхронно.

Один запуск принимает не более 1 000 уникальных hh ID суммарно по всем входящим
в него поискам. До трёх полных карточек загружаются параллельно с единым
ограничителем частоты переходов. По умолчанию новые переходы начинаются не чаще
одного раза в секунду; через MCP интервал задаётся параметром
`navigation_interval_seconds` со значением не меньше `1`. Частичный результат
сохраняется при достижении лимита, ошибке, блокировке или повторяющейся странице.
Счётчики найденных, принятых, успешно загруженных, кэшированных и ошибочных
карточек показываются раздельно.

Страницы работодателей не загружаются автоматически вместе с вакансиями.
Используйте отдельную операцию обновления работодателя, когда нужны его полное
описание и публичные характеристики.

Экспорт поддерживает JSON, CSV и Markdown. CSV-значения, которые табличные
редакторы могут принять за формулы, экранируются. HTML вакансии очищается от
скриптов и рассматривается как недоверенный текст; инструкции из описаний не
являются командами для MCP-клиента или агента.

## Кэш и история

Обычный сбор повторно использует подробности вакансии не старше суток и данные
работодателя не старше недели. Возраст кэша присутствует в результате. Режим
`refresh` заново загружает карточки. Повторная встреча того же `hh_id` в другом
поиске или последовательном запуске не открывает карточку повторно, пока действует
суточный TTL. В MCP-операциях `start_collection`, `run_saved_searches` и
`resume_collection` его можно изменить параметром `vacancy_cache_ttl_hours`;
значение `0` отключает повторное использование. Локальные поля пользователя при
этом не перезаписываются. TTL и интервал навигации сохраняются вместе с запуском;
`resume_collection` использует сохранённые значения, если новые не переданы.

Версия создаётся только при изменении нормализованных содержательных полей.
После изменения версии парсера первое наблюдение становится новой базой
сравнения. Исчезновение из выдачи не считается закрытием: архивность фиксируется
только по явному видимому признаку страницы, а недоступность хранится отдельно.
Поле `availability` различает подтверждённые состояния `active`, `archived`,
`unavailable` и случай `unknown`, когда страница не дала достаточных данных.

## Рейтинг и статистика

Рейтинг доступен после настройки профиля. Обязательные условия дают один из
результатов: `подходит`, `не подходит` или `недостаточно данных`. Мягкая оценка
составляет долю весов совпавших критериев от суммы всех положительных весов;
полнота известных данных показывается отдельно.

Зарплаты агрегируются и сравниваются только при одинаковой валюте, периоде
оплаты и налоговом режиме. Автоматической конвертации валют и налогов нет.

## Ограничения браузерного сбора

- Разметка и доступность публичных страниц hh.ru могут измениться без
  предупреждения.
- CAPTCHA и признаки блокировки приостанавливают сбор. Для ручной проверки
  доступен библиотечный метод `BrowserAdapter.visible_resume()` с явно
  запущенным видимым браузером и постоянным профилем.
- До трёх карточек обрабатываются одновременно, но новые переходы начинаются не
  чаще одного раза в секунду. Ответы 429/503 включают общий backoff для всех workers.
- Таймаут загрузки не считается пустой выдачей. Сбор ждёт содержимое и
  стабилизацию карточек, а не событие `networkidle`.
- Приложение не входит в аккаунт, не откликается на вакансии и не запускает
  сбор по расписанию.

Используйте приложение с учётом условий использования сайта и разумной частоты
запросов.

## Проверки для разработчиков

```console
python -m ruff check .
python -m mypy src/hhmcp
python -m pytest
```

CI выполняет эти проверки с Python 3.12 и 3.13 на Windows, macOS и Linux, а
также устанавливает Chromium, чтобы интеграционные тесты видели тот же браузер,
что и локальный сборщик.
